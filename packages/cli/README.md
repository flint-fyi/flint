## Detailed-report highlighting

Published builds bundle only the TypeScript grammar, Nord theme, and Oniguruma engine used by `formatCode`.
Shiki and its ANSI renderer are build dependencies, not runtime dependencies.
The highlighter stays in the lazy detailed-presenter chunk; brief reports do not load it.

`@shikijs/cli` has no highlighter-injection API.
The build redirects only that package's bare `shiki` import to `src/presenters/detailed/shiki.ts`, which implements the two public exports used by its ANSI renderer.
This is a version-specific build integration, not a supported Shiki extension point.
It leaves the upstream renderer, ansis color detection, tokenization, and WASM unchanged.
Other packages' Shiki imports are not redirected.

### Updating Shiki

Keep `@shikijs/cli` and `shiki` pinned to the same version in the development catalog.
For each upgrade:

1. Inspect the ANSI renderer's imports and calls; update the restricted highlighter if its contract changes.
2. Review the generated package licenses in `dist/licenses.txt` and refresh the embedded-asset notices in `THIRD_PARTY_NOTICES.md`.
   Follow Shiki's versioned lockfile to the grammar/theme notices and `vscode-oniguruma`'s license and third-party notices; the latter covers the embedded WASM, not just its JavaScript bindings.
3. Run `pnpm test --project cli --run`.
   The highlighter tests compare TypeScript tokens and the Nord theme against upstream Shiki.
4. Run `pnpm build` before packing or publishing.
   The CLI build clears `dist` to remove obsolete hashed chunks.
   Inspect a `pnpm --filter @flint.fyi/cli pack` tarball for both license files, only the selected grammar/theme, and absence of runtime Shiki dependencies.
   Compare detailed-report output from packed consumers before and after the upgrade, including Unicode, multiline code, `NO_COLOR`, `FORCE_COLOR=0/1/2/3`, and color flags.

`inlinedDependencies` is generated by tsdown for dependency auditing; it does not replace the shipped license notices.
Source development uses the normal upstream renderer, so source-only tests are not sufficient to verify this integration.
