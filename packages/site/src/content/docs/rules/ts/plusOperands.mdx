JavaScript's `+` operator has two distinct behaviors: arithmetic addition for numbers and string concatenation for strings.
When operands of different types are used, implicit type coercion occurs, which can lead to unexpected results and bugs.

This rule enforces that both operands of a `+` operation are of the same type and are either `bigint`, `number`, or `string`.
It also catches attempts to mix `bigint` and `number` types, which causes a runtime error in JavaScript.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const str = "Count: ";
const num = 5;
const result = str + num;
```

```ts
const num = 5;
const str = "10";
const result = num + str;
```

```ts
const bigint = 5n;
const num = 10;
const result = bigint + num;
```

```ts
const bool = true;
const num = 5;
const result = bool + num;
```

```ts
let count = 0;
count += "1";
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const a = 5;
const b = 10;
const result = a + b;
```

```ts
const greeting = "Hello, ";
const name = "world";
const result = greeting + name;
```

```ts
const a = 5n;
const b = 10n;
const result = a + b;
```

```ts
const count = 5;
const label = "Count: ";
const result = label + String(count);
```

```ts
let total = 0;
total += 10;
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you intentionally use the `+` operator for type coercion and string concatenation with mixed types, you may want to disable this rule.
However, it's generally better to use explicit type conversions like `String()` or `Number()` for clarity.

Some legacy codebases may rely on implicit coercion behavior, in which case this rule may produce many reports.
You might consider using [Flint disable comments](/directives) and/or [configuration file disables](/configuration#files) for those specific situations instead of completely disabling this rule.
