<RuleSummary plugin="ts" rule="unnecessaryTypeConstraints" />

Type parameter constraints restrict the types that callers can supply.
The direct constraints `extends any` and `extends unknown` allow every type, so they do not restrict the type parameter.
This rule reports only those direct constraint keywords and does not report aliases, unions containing `any`, parenthesized `any`, or `keyof any`.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
function identity<Value extends any>(value: Value) {
	return value;
}
```

```ts
interface Container<Value extends unknown> {
	value: Value;
}
```

```ts
const identity = <Value extends unknown>(value: Value) => value;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
function identity<Value>(value: Value) {
	return value;
}
```

```ts
interface StringContainer<Value extends string> {
	value: Value;
}
```

```ts
const identity = <Value>(value: Value) => value;
```

```ts
type AnyAlias = any;

interface GeneratedContainer<Value extends AnyAlias> {
	value: Value;
}
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

Do not use this rule when generated declarations or an external API convention require explicit top-type constraints, even though those constraints do not narrow the accepted types.
