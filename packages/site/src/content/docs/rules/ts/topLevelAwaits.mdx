Top-level await (introduced in ES2022) allows using `await` at the module level.
While convenient, it can cause issues:

- Modules using top-level await block their dependents until the await resolves
- This can cause unexpected delays in application startup
- It makes module loading order less predictable

## Examples

### Top-Level Await

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const config = await import("./config.json");
export const apiUrl = config.apiUrl;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
let config: Config;

export async function getConfig() {
	if (!config) {
		config = await import("./config.json");
	}
	return config;
}
```

</TabItem>
</Tabs>

### Data Fetching

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const data = await fetch("/api/data").then((r) => r.json());
export { data };
```

</TabItem>
<TabItem label="✅ Correct">

```ts
export async function fetchData() {
	return fetch("/api/data").then((r) => r.json());
}
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you're intentionally using top-level await for module initialization and understand the implications for module loading, you may disable this rule.
Top-level await can be appropriate for scripts that aren't imported by other modules.
