Enforces using `\w` instead of `[a-zA-Z0-9_]` and `\W` instead of `[^a-zA-Z0-9_]` in regular expressions.
The escape sequences are more concise and widely recognized.

## Examples

### Word Character Class

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /[0-9a-zA-Z_]+/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /\w+/;
```

</TabItem>
</Tabs>

### Negated Word Character Class

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /[^0-9a-zA-Z_]/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /\W/;
```

</TabItem>
</Tabs>

### With Ignore Case Flag

When the `i` flag is used, `[a-z]` already covers both lowercase and uppercase letters:

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /[0-9a-z_]/i;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /\w/i;
```

</TabItem>
</Tabs>

### RegExp Constructor

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = new RegExp("[0-9a-zA-Z_]+");
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = new RegExp("\\w+");
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If your codebase has an established convention of using explicit character classes for readability, or if you need consistency with patterns that use partial word character ranges (like `[a-z0-9]`), you might prefer to disable this rule.
