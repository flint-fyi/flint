The optional chaining operator (`?.`) provides a concise way to safely access nested properties that might be `null` or `undefined`.
Using logical AND (`&&`) for this purpose works but is less precise, as it short-circuits on any falsy value rather than specifically on nullish values.

The optional chaining operator is more explicit about intent and produces cleaner code.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const value = foo && foo.bar;
```

```ts
const value = foo.bar && foo.bar.baz;
```

```ts
if (user && user.profile && user.profile.name) {
	console.log(user.profile.name);
}
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const value = foo?.bar;
```

```ts
const value = foo.bar?.baz;
```

```ts
if (user?.profile?.name) {
	console.log(user.profile.name);
}
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If your codebase relies on the falsy short-circuiting behavior of logical AND, you might need to disable this rule for specific cases.
However, consider refactoring to be more explicit about null/undefined checks.
