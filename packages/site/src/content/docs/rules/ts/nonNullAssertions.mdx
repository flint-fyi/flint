The non-null assertion operator (`!`) tells TypeScript to trust that a value is not `null` or `undefined`.
This bypasses TypeScript's strict null checking and can mask potential bugs when the value actually is `null` or `undefined` at runtime.

Prefer type guards, nullish coalescing (`??`), or optional chaining (`?.`) instead.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
declare const value: string | null;

value!.toUpperCase();
```

```ts
declare const object: { property: string } | null;

object!.property;
```

```ts
declare const callable: (() => void) | null;

callable!();
```

</TabItem>
<TabItem label="✅ Correct">

```ts
declare const value: string | null;

value?.toUpperCase();
```

```ts
declare const object: { property: string } | null;

object?.property;
```

```ts
declare const value: string | null;

if (value !== null) {
	value.toUpperCase();
}
```

```ts
declare const value: string | undefined;

const result = value ?? "default";
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you are migrating a large codebase to strict null checking and need to temporarily use non-null assertions, you may disable this rule.
Some codebases may also have well-understood patterns where non-null assertions are safe and documented.
