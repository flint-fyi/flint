The `const` keyword creates a read-only reference to a value, preventing reassignment.
While properties of const objects and elements of const arrays can be mutated, the binding itself cannot be reassigned.
Attempting to reassign a const variable results in a runtime error.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
// @errors: 2588
const value = 1;
value = 2;
```

```ts
// @errors: 2588
declare const getOtherValue: () => string;
declare const getValue: () => string;
// ---cut---
const result = getValue();
result = getOtherValue();
```

```ts
// @errors: 2588
const counter = 0;
counter++;
```

```ts
// @errors: 2588
declare const object: { property: string };
// ---cut---
const { property } = object;
property = "new value";
```

```ts
// @errors: 2588
declare const items: string[];
declare const processItem: (item: string) => string;
// ---cut---
for (const item of items) {
	item = processItem(item);
}
```

</TabItem>
<TabItem label="✅ Correct">

```ts
let value = 1;
value = 2;
```

```ts
const object = { value: 1 };
object.value = 2;
```

```ts
const array = [1, 2, 3];
array.push(4);
```

```ts
declare const object: { property: string };
// ---cut---
const { property } = object;
console.log(property);
```

```ts
declare const items: string[];
declare const processItem: (item: string) => string;
// ---cut---
for (let item of items) {
	item = processItem(item);
}
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If your codebase relies on non-standard behavior that involves reassigning constant variables (which is highly discouraged), you might choose to disable this rule.
For example, if you target a legacy runtime with non-standard JavaScript semantics, standard practices may not apply to you.
