<RuleSummary plugin="ts" rule="importSelf" />

A module importing itself creates a circular dependency that serves no purpose.
This typically occurs accidentally during refactoring or copy-pasting code.
Self-imports can cause issues with module initialization order and are likely indicative of a bug.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
// utils.ts
import { helper } from "./utils";
```

```ts
// index.ts
import * as self from "./index";
```

</TabItem>
<TabItem label="✅ Correct">

```ts
// utils.ts
import { helper } from "./other-utils";
```

```ts
// index.ts
import { value } from "./module";
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you have a rare architectural pattern or other build tooling that intentionally uses self-imports, you may disable this rule.
However, self-imports typically indicate a code organization problem that should be addressed.
