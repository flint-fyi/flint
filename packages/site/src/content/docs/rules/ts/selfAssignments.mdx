Self-assignments where a variable is assigned to itself have no effect and typically indicate an incomplete refactoring or a copy-paste error.
These assignments serve no purpose and should be removed or corrected to assign the intended value.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
// @errors: 2588
declare const value: any;
// ---cut---
value = value;
```

```ts
// @errors: 2588
declare const count: any;
// ---cut---
count &&= count;
```

```ts
declare const flags: any;
// ---cut---
flags.value ||= flags.value;
```

```ts
// @errors: 2588
declare const data: any;
// ---cut---
data ??= data;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
// @errors: 2588
declare const newValue: any;
declare const value: any;
// ---cut---
value = newValue;
```

```ts
// @errors: 2588
declare const count: any;
declare const otherCount: any;
// ---cut---
count &&= otherCount;
```

```ts
// @errors: 2588
declare const defaultFlag: any;
declare const flag: any;
// ---cut---
flag ||= defaultFlag;
```

```ts
// @errors: 2588
declare const data: any;
declare const fallbackData: any;
// ---cut---
data ??= fallbackData;
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

There are rarely valid reasons to use self-assignment.
In cases where you need to trigger getters/setters or proxies, consider adding a comment explaining the intentional self-assignment.
