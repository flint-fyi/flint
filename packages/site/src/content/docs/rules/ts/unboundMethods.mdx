<RuleSummary plugin="ts" rule="unboundMethods" />

When class methods are referenced without being bound, they lose their `this` context.
This is a common source of bugs in JavaScript and TypeScript.

## Examples

### Method Reference

<Tabs>
<TabItem label="❌ Incorrect">

```ts
class Logger {
	log(message: string): void {
		console.log(this.prefix + message);
	}
}
const logger = new Logger();
const unbound = logger.log;
unbound("hello"); // 'this' is undefined
```

</TabItem>
<TabItem label="✅ Correct">

```ts
class Logger {
	log(message: string): void {
		console.log(this.prefix + message);
	}
}
const logger = new Logger();
const bound = logger.log.bind(logger);
bound("hello"); // 'this' is correct
```

</TabItem>
</Tabs>

### Callback Patterns

<Tabs>
<TabItem label="❌ Incorrect">

```ts
class Service {
	fetch(): Promise<void> {}
}
const service = new Service();
setTimeout(service.fetch, 1000);
```

</TabItem>
<TabItem label="✅ Correct">

```ts
class Service {
	fetch(): Promise<void> {}
}
const service = new Service();
setTimeout(() => service.fetch(), 1000);
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you're using arrow function methods or class property initializers that auto-bind,
this rule may produce false positives.
