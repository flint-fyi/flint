Reports trivially nested assertions in regular expressions that can be simplified.
A lookaround is trivially nested when it contains exactly one element that is itself an assertion (anchor or another lookaround of the same direction).

## Examples

### Anchor Inside Lookaround

Wrapping an anchor like `$`, `^`, `\b`, or `\B` in a lookaround is unnecessary.

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /(?=$)/;
const boundary = /(?=\b)/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /$/;
const boundary = /\b/;
```

</TabItem>
</Tabs>

### Nested Lookaround of Same Direction

A lookahead containing only another lookahead (or lookbehind containing lookbehind) is redundant.

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /(?=(?=a))/;
const behind = /(?<=(?<=a))/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /(?=a)/;
const behind = /(?<=a)/;
```

</TabItem>
</Tabs>

### RegExp Constructor

The rule also checks regex patterns in `RegExp` constructor calls.

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = new RegExp("(?=$)");
const boundary = RegExp("(?=\\b)");
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = new RegExp("$");
const boundary = RegExp("\\b");
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you intentionally keep nested structures for code clarity or documentation purposes, you may disable this rule.
