Reports consecutive identical elements in regular expressions and suggests using quantifiers instead.
Writing `a{3}` is more concise and readable than `aaa`.

## Examples

### Repeated Characters

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /aaa/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /a{3}/;
```

</TabItem>
</Tabs>

### Escape Sequences

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /\d\d\d\d-\d\d-\d\d/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /\d{4}-\d{2}-\d{2}/;
```

</TabItem>
</Tabs>

### Character Classes

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /[a-z][a-z]/;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /[a-z]{2}/;
```

</TabItem>
</Tabs>

### Dots

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = /../;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = /.{2}/;
```

</TabItem>
</Tabs>

### RegExp Constructor

<Tabs>
<TabItem label="❌ Incorrect">

```ts
const pattern = new RegExp("aaa");
```

</TabItem>
<TabItem label="✅ Correct">

```ts
const pattern = new RegExp("a{3}");
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If your project has a style guide that prefers explicit repetition for clarity, or if you are programmatically generating regular expressions where repetition is easier to produce, you might want to disable this rule.
