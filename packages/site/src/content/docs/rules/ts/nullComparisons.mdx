Using loose equality operators (`==` or `!=`) to compare a value with `null` will also match `undefined` due to JavaScript's type coercion rules.
This implicit behavior can lead to unexpected results when you intend to check specifically for `null` or specifically for `undefined`.

Using strict equality (`===` or `!==`) makes the comparison explicit and avoids ambiguity about which values are being matched.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```ts
if (value == null) {
	console.log("value is null or undefined");
}
```

```ts
const hasValue = input != null;
```

</TabItem>
<TabItem label="✅ Correct">

```ts
if (value === null) {
	console.log("value is null");
}
```

```ts
if (value === null || value === undefined) {
	console.log("value is null or undefined");
}
```

```ts
const hasValue = input !== null && input !== undefined;
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you intentionally use `== null` as a shorthand to check for both `null` and `undefined`, you may want to disable this rule.
Some codebases prefer this pattern for its brevity.
