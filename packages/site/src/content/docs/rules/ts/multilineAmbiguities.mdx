When a line ends with an expression and the next line starts with certain characters (parentheses, brackets, or template literals), JavaScript may interpret them as a continuation of the previous line rather than separate statements.
This can lead to unexpected behavior and runtime errors that are difficult to debug.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

{/* prettier-ignore-start */}

```ts
declare const doSomething: () => void;
declare const expression: string;
declare const identifier: (arg: string) => string;
// ---cut---
const value = identifier(expression)
doSomething();
```

```ts
declare const getArray: { value: string }[];
// ---cut---
const data = getArray
[0].value;
```

```ts
declare const calculate: (strings: TemplateStringsArray) => string;
// ---cut---
const result = calculate
`template literal`;
```

```ts
declare const b: (arg: { execute(): void }) => { execute(): void };
declare const c: { execute(): void } | undefined;
declare const d: { execute(): void };
// ---cut---
function process() {
	const a = b
	(c || d).execute();
}
```

{/* prettier-ignore-end */}

</TabItem>
<TabItem label="✅ Correct">

```ts
declare const expression: { doSomething(): void };
declare const identifier: string;
// ---cut---
const value = identifier;
expression.doSomething();
```

```ts
// @errors: 2551 -- property typo (did you mean?)
declare const getArray: { value: string }[];
// ---cut---
const data = getArray;
[0].value;
```

```ts
declare const calculate: (strings: TemplateStringsArray) => string;
// ---cut---
const result = calculate;
`template literal`;
```

```ts
declare const b: string;
declare const c: { execute(): void } | undefined;
declare const d: { execute(): void };
// ---cut---
function process() {
	const a = b;
	(c || d).execute();
}
```

</TabItem>
</Tabs>

## Options

This rule is not configurable.

## When Not To Use It

If you consistently use semicolons and have tooling that enforces their presence, this rule may be unnecessary.
However, having this rule enabled provides an additional safety net against accidental multiline ambiguities.
