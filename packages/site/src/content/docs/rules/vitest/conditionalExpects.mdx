<RuleSummary plugin="vitest" rule="conditionalExpects" />

Calling `expect` inside a conditional statement (`if`, `switch`, a ternary, `&&`/`||`/`??`, or a `catch` block) means the assertion may never run at all.
If the condition is never met, the test passes without actually checking anything.

The same is true of a `.catch()` handler.
It only runs if the promise rejects, so a promise that resolves means the assertion never runs.
Assertion failures thrown inside the handler can also be swallowed by the rest of the promise chain.

This rule reports both cases separately, since they have different fixes.

## Examples

### Conditional statements

<Tabs>
<TabItem label="❌ Incorrect">

```ts
test("something", () => {
	if (something) {
		expect(something).toBe(true);
	}
});
```

```ts
test("something", () => {
	something ? expect(something).toBe(true) : null;
});
```

</TabItem>
<TabItem label="✅ Correct">

```ts
test("something", () => {
	expect(something).toBe(true);
});
```

```ts
test("something", () => {
	expect.assertions(1);
	if (something) {
		expect(something).toBe(true);
	}
});
```

</TabItem>
</Tabs>

### `.catch()` handlers

Prefer asserting on the rejection directly, so the assertion runs whether or not the promise rejects.

<Tabs>
<TabItem label="❌ Incorrect">

```ts
promise.catch(() => {
	expect(true).toBe(false);
});
```

</TabItem>
<TabItem label="✅ Correct">

```ts
test("something", async () => {
	await expect(promise).rejects.toThrow();
});
```

```ts
test("something", async () => {
	expect.assertions(1);
	await promise.catch((error) => {
		expect(error).toBeDefined();
	});
});
```

</TabItem>
</Tabs>

## Options

### `expectAssertions`

Whether to allow `expect` calls inside conditionals when the test case also calls `expect.assertions(...)`.
Defaults to `false`.

`expect.assertions(...)` tells Vitest exactly how many assertions the test must run, so a conditional `expect` that gets skipped will still fail the test for not matching that count.

Examples of **correct** code with `{ expectAssertions: true }`:

```ts
test("something", () => {
	expect.assertions(1);
	if (something) {
		expect(something).toBe(true);
	}
});
```

## When Not To Use It

If your test suite relies on other mechanisms to guarantee conditional assertions still run, such as always calling `expect.assertions(...)` without opting into the `expectAssertions` option, this rule might report cases you've already accounted for.
