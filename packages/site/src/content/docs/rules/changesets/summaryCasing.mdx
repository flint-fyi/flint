Changesets copies the summary of each changeset into the `CHANGELOG.md` of every package it releases.
Starting every summary with the same letter case makes those changelog entries consistent to read.

This rule checks the first letter of a changeset's summary, after any conventional commit prefix.
By default, it reports summaries that start with a lowercase letter.

## Examples

## Options

### `casing`

> Type: `"lowercase" | "uppercase"`
>
> Default: `"uppercase"`

Which letter case the first letter of changeset summaries must be.

```ts
changesets.rules({
	summaryCasing: {
		casing: "lowercase",
	},
});
```

## When Not To Use It

If your project's changesets are written by many contributors and you don't review changelog entries for consistency, this rule may produce reports that nobody acts on.
You might prefer to leave this rule disabled until your project reviews changelog formatting.
