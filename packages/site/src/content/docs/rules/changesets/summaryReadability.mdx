Changesets copies the summary of each changeset into the `CHANGELOG.md` of every package it releases.
Those changelog entries are read by the package's users, not by commit tooling.

Conventional commit prefixes such as `feat:` or `fix(core):` label commits for tools that parse Git history.
In a changelog entry, they repeat information already recorded by the version bump in the changeset's frontmatter.

A changeset whose frontmatter lists packages but has no summary creates a changelog entry that doesn't describe its change.
Changesets created with `changeset add --empty` list no packages and are not reported.

This rule reports summaries that start with a conventional commit prefix and changesets that are missing a summary.
It removes conventional commit prefixes when run with `--fix`.

## Examples

<Tabs>
<TabItem label="❌ Incorrect">

```md
---
"example-package": minor
---

feat: Added a new option.
```

```md
---
"example-package": patch
---

fix(parser)!: Fixed a crash on empty files.
```

```md
---
"example-package": patch
---
```

</TabItem>
<TabItem label="✅ Correct">

```md
---
"example-package": minor
---

Added a new option.
```

```md
---
"example-package": patch
---

Fixed a crash on empty files.
```

```md
---
---
```

</TabItem>
</Tabs>

## When Not To Use It

If your project publishes changelogs that are generated from conventional commit messages rather than from changeset summaries, the prefixes may be read by your release tooling.
You might then prefer to disable this rule rather than change that tooling.
